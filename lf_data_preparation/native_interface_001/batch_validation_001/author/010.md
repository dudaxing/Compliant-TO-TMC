# 薄批量入口：源码边界与最小检查建议

状态：source-only。只读当前入口、任务校验与已有模拟/保存 JSON 测试；未导入产品、构模、读取数组或执行测试。新批量功能应顺序复用现有 evaluate_native，每例各一次；不重写求解、缓存写入或摘要数学。

现有 task 比较只去 task_id/geometry，其余字段应原值保留，包含 material、gamma、alpha/Lr、input 目标、output、constraints、背景对称、工件、reference_state 和显式 path。geometry JSON 还承担厚度、域和 region_tags；因此本例 task 必须绑定本例 geometry_id/descriptor_sha256，各例 case_family/thickness_mm/model_extent/region_tags 和 grid origin/axes/extent 相同。允许 shape/cell_size 不同；这仅核声明物理条件，不证明 NPZ 内容、节点选择或离散等价。

native_mean 接受 complete/mechanical、full/chunk256；控制器接受 tangent/port_projection。initial_guess 目前在构模之后才检查，因此批量应在任何 evaluate 前对三个枚举做窄预检。新 JSON options 只转发现有入口参数，未知键应预检拒绝；不新加 reference/view 参数或隐式切换目标。控制器时限与整体批量/CLI时限不同，不相加后假称资源覆盖。

native_evaluate 处理 OSError/ValueError/KeyError/TypeError，TMCError 是 ValueError。普通 returned status=failed 已带保存 partial，target_response 为 null，last_accepted 保留。批量遇到非 success 就停止并把后续项标 not_run、说明前一项失败；不得借旧参考或补图后改其 status。RuntimeError 等监督中止不得转成“继续下一例”。如果批量只记录普通逃逸异常，保留原 class/code/reason，不猜是否有 accepted prefix；也不吞 KeyboardInterrupt/SystemExit。

建议约七组测试（可小参数化），全部 mock evaluate transport，真实科学计数为零：

1. 两例成功：顺序每例一次，默认/显式选项准确原传；原响应包含不同目标、终点、工件/null、参考和图标识，批量仅关联自身返回值，不合并资格。
2. 第2 task 的 E 或 path 不同：所有 evaluate 调用为零，不改变目标或首例任务。
3. 第2 geometry 端口坐标不同和 task 错绑：两种差异均在首例 evaluate 之前拒绝。
4. 未知选项/非法枚举和已有输出路径：全批零调用，既有文件原字节保持。
5. 首例 returned failed：自身 partial/原 failure 保留，下一例未调用并有明确 not_run 理由。
6. 普通异常逃逸与监督 RuntimeError：停止，不调用后续例；普通异常不伪造结果，监督异常不被吞成继续。
7. CLI 在任意 cwd 使用显式 repo：输入、任务、输出按 repo 定位，成功/失败退出码与实际摘要一致；只依已有薄入口，无科学调用。

现有21项测试提供单例响应与mock语义背景，本次不重跑或复制整个旧 suite。目标态与请求终点已有分别字段（例如循环峰值与回零），批量必须保留；成功 short path 也不能写成已执行原任务最大目标。
