两份 .025 旧结果都真实 PASS、4原态、14F/9T/1solve、0失败尝试/0二分；fine 的每次全域精度参考覆盖12800 cells，8HP为102400 element-precision instances，约为 coarse 的4倍，实际成本则约5.43倍。不能由最近 coarse .001 的4HP/39.579秒推定 fine .025 参考也能在180秒内完成。

必须显式保留 `minimum_increment=0.0000625 mm`。旧两例 .025 settings 全部相同，只有时间限300/1500秒不同；新 `evaluate_native` 不显式给最小增量时会按首目标 .005/16 得到 .0003125 mm，属于无意改变求解设置。其余 tolerance=1e-9、constraint=1e-10、max_checks25、Armijo1e-4、12 backtracks、4 bisections 等沿当前既有默认值即可，勿同时传完整 settings 和单独限额而触发冲突。

新的生产预算建议：coarse controller300秒、fine controller1800秒；两例同一个 whole-helper2400秒 /outer2460秒、8 GiB 采样 RSS，一次连续执行。匹配旧 .025 生产总耗时1275.697496秒；coarse按1.5×176.48+30向上取300，fine按1.5×1099.22+90向上取1800，并为全 wrapper 的 imports/构模/缓存写出/summary 留300秒。controller 限额只覆盖求解，不覆盖这些外围操作；whole-helper/F3必须覆盖它们。该值是新窗口建议，旧闭卡不能续用。这里没有冻结卡或判定授权。

新生产完整通过后，每例另冻独参卡，按实际 N 对全部接受态执行新80/120精度，即2N HP，包括实际二分态。保留原 `Audit.run_state/GATES/HP/scatter/方向` 数学，仅适配真实 batch receipt、current sources、task/model、shape 和 targets 身份。当前5个历史 core 字节已变，旧独参均仅为可行性与成本来源，不能赋新资格。若实际仍N=4，建议 coarse240/270秒、fine900/960秒，各8 GiB；若N改变，应依100.633719或546.319825秒×N/4重新确认预算后才冻结。现有180秒 real-API包装的 coarse/.001/4F/3T硬绑定不能直接用于两例新结果。
