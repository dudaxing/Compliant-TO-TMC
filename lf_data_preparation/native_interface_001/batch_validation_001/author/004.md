# Sequential native batch candidate

Source only, not installed or run. Proposed installation: `native_batch.py` → `hf_repo/src/hf_eval/native_batch.py`; `evaluate_native_batch.py` → `hf_repo/scripts/evaluate_native_batch.py`. No existing API, response module or mechanics source is changed.

Public function: `evaluate_native_batch(manifest_path, output_directory, *, repo_root=None) -> dict`. It calls existing `evaluate_native` once for each attempted case, in declared order. The first non-success stops the batch; no concurrent work, retries, repair, ranking or qualification merge. Existing individual response.json files remain authoritative.

Example manifest (paths/tasks are placeholders; this is not an executed science card):

```json
{
  "schema_version": "hf-native-batch-manifest-1.0",
  "options": {
    "targets": [0, 0.005, 0.010, 0.025],
    "minimum_increment": 0.0000625,
    "time_limit_seconds": 1800,
    "response_mode": "complete",
    "tangent_mode": "full",
    "initial_guess": "tangent"
  },
  "cases": [
    {"label": "coarse", "geometry": "jobs/coarse/geometry.json", "task": "jobs/coarse/task.json", "output": "results/batch_001/coarse"},
    {"label": "fine", "geometry": "jobs/fine/geometry.json", "task": "jobs/fine/task.json", "output": "results/batch_001/fine"}
  ]
}
```

After installation, from any directory:

```powershell
& <HF-Python> <repo>/hf_repo/scripts/evaluate_native_batch.py --repo <repo> --manifest jobs/batch.json --output results/batch_001
```

Every relative manifest/geometry/task/case output/batch output path is resolved against explicit repo (otherwise caller cwd), never against the manifest folder or batch folder. Absolute paths retain their location. The new batch directory owns index.json only; case outputs may be its children or elsewhere, but cannot contain the batch directory or each other. Labels and resolved outputs must be unique and every output fresh. CLI exits0 only for an all-success batch, otherwise1. Preflight refusal writes nothing.

Before each actual evaluation, raw SHA of its geometry/task JSON is checked against preflight; a change stops with an error. Before the first evaluation, reuse existing task validation; compare every task after removing only task_id and geometry, preserving descriptions, material, ports/constraints, background, body, path and all other fields. Geometry/task declared id and descriptor SHA must match. Geometry JSON must share case_family/thickness/model_extent/region_tags and grid origin/axes/extent. Shape/cell size may differ and remain recorded per case. This compares physical declarations, not arrays or discretization equivalence, mesh convergence or performance. No NPZ/model construction occurs in preflight.

Shared options use existing API names. Defaults remain complete/full/tangent, controller time180s and its first-step/16 minimum-increment rule. Explicit mechanical/chunk256/port_projection are accepted. Optional settings is a JSON object converted to existing DisplacementSettings; as in evaluate_native, it cannot be combined with explicit minimum_increment or nondefault time_limit_seconds. Unknown options are rejected. Explicit targets must exactly equal a task1.1 path; task1.0 can still request a shorter path, with task-target/endpoint distinction preserved. Overall resource windows and cooperative stop belong to an external execution card; this product does not manage resources.

Compact index records manifest/input/response raw SHA and path scopes, shared declarations/options, each case's own identity, path, target/endpoint/last/maximum-stroke response, R/q/J fields, calls, failure, reference/views and original producer flags. Unattempted cases keep response fields null and status not_run, with a reason naming the stopping case. Ordinary typed failures escaping the API are recorded as batch_call errors, with response=null if no response returned. Other exceptions (including a resource RuntimeError) are recorded by an interrupt handler as an interrupted index and immediately re-raised; finally only saves the index; no next case runs. Native controller failures returned by the API retain their cached prefix. Batch HF5/ranking flags remainfalse, regardless of individual source claims.

Tradeoffs: 220-line module plus 26-line CLI; the original task/settings validators are reused rather than duplicated. Declaration comparison deliberately allows different grids but does not certify a matched mesh. No automatic independent reference, view generation, optimizer or new kernel is introduced. Functional JSON/mock tests and any real two-case run require their separately frozen windows.
