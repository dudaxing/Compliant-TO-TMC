# 薄原生评价接口的最小功能验证

本候选只验证 JSON 响应与调用集成；作者阶段没有导入 HF、读取 NPZ、运行测试或新增科学计算。既有参考的机械资格仅通过同结果身份引用，测试通过不产生新的 forward、接触、压力、网格、HF5 或独立 HP 资格。

建议一次连续的新纯功能窗口：helper 120 s / outer 150 s / 8 GiB，首个失败即停、没有修复重试。原数值执行卡已经关闭，本窗口不能续用其资源。大部分工作是少量已保存 JSON 与被替代的 solver/writer 调用；不需要 200 s / 230 s，也不应运行现有科学回归测试。

| 情况 | 既有 JSON 来源 | 必须验证的结果 |
|---|---|---|
| 完整 2 mm、4 mm 工件路径 | `lf_data_preparation/native_workpiece_001/{right_margin_cycle_001,right_margin4_cycle_001}/run_001/result/result.json` 与各自 `reference/summary.json` | 每个实际 state 与原值一致；最大加载位移、最后卸载态、signed total/material/regularization 力分开；同结果全实际 N/2N 参考可引用，但压力/接触/HF5 不升级 |
| 无工件的 fine 0.025 mm | `lf_data_preparation/native_fine_task_025_001/result/result.json` | 全4态原值、无工件为 null、没有伪造 zero-body 力；无传入参考时不授 HP 资格 |
| 单个真实失败前缀 | `lf_data_preparation/native_workpiece_001/enlarged_square_contact_001/run_001/result/result.json` | failed9；last=0.86875 mm、original index7 且不是原目标；保持 invalid_J 原 code/reason；target_response=null，partial 不冒成功 |
| 不匹配或不完整参考 | 将旧2mm summary 给新4mm；或从新真实 summary 产生仅用于负例的副本 | result SHA 不匹配、缺实际 state、HP2N 覆盖不足或 status非pass时必须不授 HP 资格；负例只修改测试目录 JSON，不修改原证据 |
| 一次组合调用 | solver、cached writer 用替身；纯 JSON summary 保持正常读取或受控替身 | solve 1次→write 1次，传入同一个结果对象；不预构模、不重试、选项原值传递，默认 tangent 与显式 port_projection 均明确 |
| 阶段错误 | input/solve/persistence/summary 中的受控错误 | stage、原 code（无 code 则 null）、原 class/reason；下游调用停止，不能调用修复 solver 或从错误制造目标响应 |
| 任意 cwd CLI | repo 与运行 cwd 不同，geometry/task/output 采用 repo 相对路径 | 一次 evaluate 调用拿到正确绝对路径及明确 initial_guess；CLI 只读 JSON，不触发实际 forward |
| 任务与路径终点区别 | `lf_data_preparation/native_fine_mean_001/result/result.json` 实际成功2态到0.001 mm，任务目标0.025 mm未执行 | 保留路径成功与请求终点响应；任务目标响应为null，不人工修改原canonical descriptor |
| 既有视图身份 | 2/4mm同一view中的各自summary.json和原3PNG+各自GIF | 正例仅给同case动画；重复label、唯一label交换或failed9错结果不能借4mm GIF；负例仅复制原图片bytes，无新绘图 |

最终候选为10个test函数／21个pytest cases，另在同一窗口实际调用纯JSON formatter4次，保存2mm、4mm、no-workpiece、failed-prefix的紧凑response，供人工查看。mock transport入口共计划7次solver、6次cached-writer（含刻意抛错），它们不是实际HF调用。

worker `execute_interface_tests.py --repo . --protocol <stage>/functional_protocol.json` 读取 protocol的 `fixture_manifest_file/tests_directory/output_directory/expected_tests=21`。每test之前与phase末检查cooperative stop、whole-helper120s和sampled8GiB；F3外部150s。pytest `-x`首错停，无重试。真实model/F/T/controller/HP/geometry/nodal/array-load调用由source-origin/profile guard拒绝并独立计数，导入基础HF模块本身不算物理调用。

测试运行时明确 `HF_INTERFACE_TEST_REPO`（完整 Git 根）；实际 worker会设置它。测试数据使用已闭卡的15个真实JSON身份，并固定其 SHA；不会复制完整历史证据包或读取数组。原reference声明的29个source角色仅核raw .py bytes；5个原image身份由view JSON声明，作者阶段没有打开图片。实际执行由root新的阶段负责，候选没有导入或运行任何测试/API。
