最近窄审同时检查输入归属、物理／原构模门与同网格真实成本。结论是先让新的 `gripper_native_fine` 完整经过既有 evaluate_native，而不是继续增加读数组诊断或重写求解核心。新包装只调一次 API，成功才在独立纯进程显示。原工件与掩码／节点兼容性由这一实际 API 的构模门判定。

保留完整25目标、原物理条件和原生产门。显式复用旧机械选项及全部 DisplacementSettings（仅 clock 新设），避免字面默认选择不同的力／切线模式或最小增量。原四段同网格记录的实际耗时合计15230.27秒，尚缺一段；预算据此拟18000／19000／19060秒、8GiB，新几何仍可能只产生 partial。

源准备只新增阶段代码、协议、执行卡及恢复文档，不更改默认 HF。没有导入 HF、读取科学数组、构模、F/T、HP、求解、测试、绘图或像素检查。源码审查及 AST 不代替运行验证。本卡必须直接批准且发布／恢复核对完成后才可执行。
