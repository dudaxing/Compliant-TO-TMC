# 独立 HF 力学评估器：编程 Agent 启动任务书

你是本研究的科学计算开发 Agent，同时承担资料核查、有限元实现、验证和滚动规划工作。请依据实际上传文件开展工作，不要依据记忆补出不存在的代码、算例或结果。

## 一、研究目标与本次任务

我的整体研究是：低保真（LF）线性拓扑优化生成多样化柔顺机构，再在同一高保真（HF）任务、共同约束及明确评价预算下比较它们的真实任务表现。

当前对象是位移反向器和夹持器。本次开发目标不是重新实现 LF，也不是实现新的 HF 拓扑优化器，而是建立一个独立的正向力学评估器：

    LF 独立准备环境：生成或提取候选几何 → 保存自包含数据文件
                                            ↓
    HF 独立仓库和环境：读取数据 → 建立任务 → 非线性/接触求解
                                            ↓
                                   响应、约束、状态与可视化

LF 代码仅是前期数据生产工具。交接完成后，HF 的安装、测试、运行、后处理与后续开发均不再需要 LF 源码、LF 环境或 LF 进程。

数据交接规范、通用读取器、验证和结果存储属于 HF 体系；但 LF 特定的数据生成/导出工具必须位于 HF 仓库之外。

## 二、资料及称谓：先核对，再设计

我会提供：

1. LF 项目的代码压缩包，可能包含已经保存的优化终态、二值几何、研究索引和交接记录。
2. Frederiksen 等《A Matlab code for analysis and topology optimization with Third Medium Contact》（2026）。
3. Frederiksen 等《Improved third medium formulation for 3D topology optimization with contact》（2025）。
4. 与上述文献相关的 MATLAB 代码；实际对应关系以文件内容为准。

我此前有时写作“PMC”。请通过实际文献和源码确认方法名称。以上两篇标题对应 Third Medium Contact（TMC，第三介质接触）；不要将 PMC、TMC、MPM 或其他方法自动视为同义词。如果上传材料实际属于另一种方法，先指出冲突，不要套用错误模型。

语言优先考虑 Python。JAX 是 Python 下的可选计算/自动微分工具，不是 Java。Java 可以作为有充分理由时的备选，但不要默认把“Java”纠正成“JAX”，也不要同时维护 Python、Java 两套生产实现。先提出一种主实现路线和理由。

阅读时区分：资料已明确的事实、你实际运行得到的证据、从事实推导的判断、需要用户确定的任务参数。旧审查结论只能作为阅读线索，不能代替对本次快照的核查。记录参考代码来源并保留作者声明；公开发布前核对相应代码许可，不把论文开放获取自动等同于源码可以任意重新授权。

旧 LF 合同、文件中的阶段编号和历史授权不自动约束新 HF 项目。旧 M0—M4 不因分仓而重新打开；新 HF 使用自己的阶段编号。对旧文件中的物理语义要理解，对已过时的 current_execution 等流程字段不要机械继承。

## 三、不可越过的代码与运行边界

建议用以下逻辑分区；目录名可以调整，但依赖边界不能变：

    reference_inputs/       原始 LF 与 MATLAB 资料，只读保存
    lf_data_preparation/    LF 的可运行副本、一次性导出脚本、独立环境
    geometry_dataset/       可独立搬迁的几何与来源数据
    hf_repo/                新 HF 代码、数据接口、测试、任务配置及文档

必须遵守：

- 不把 LF 的 dmftd、MMA、AuTO、优化循环、研究驱动或整个有限元包复制到 HF 仓库。
- 不通过 import、editable install、子模块、软链接、PYTHONPATH、绝对路径或后台子进程保留隐性 LF 依赖。
- 不能把 LF 导出器放进 HF 的运行包或必需测试流程，再称其“可选依赖”。
- HF 中允许保存普通数据格式的少量验证样本和已生成的参考结果；不允许为读取它们而反序列化 LF 专有 Python 类。
- HF 可以独立实现同任务线性参照；这是新评估器的验证能力，不是重新接入旧 LF 求解器。
- MATLAB 代码用于理解、对照和开发期验证。最终 HF 生产调用不要求 MATLAB，也不要求原 MATLAB 脚本常驻进程。
- 不修改或删除原始 LF 上传包，不为 HF 搭建而清理、重构旧仓库；必要的临时操作只在工作副本中进行。

关键验收是“断开 LF”测试：只保留新 HF 仓库及数据包，在没有 LF 安装、没有 LF 路径、换一个工作目录的干净环境中，完成读取、验证、至少一个独立分析和结果输出。先做小样本，完整评估器完成后再做端到端复验。

## 四、LF 数据准备：已有结果优先，不把导出变成新的 LF 研究

先核查 LF 代码实际能生成哪些几何，以及已经保存哪些数据。优先复用并核验已有终态和二值几何；不要为了“生成输入”无条件重跑全部优化。

必须区分三类操作：读取已有结果、从已有密度导出几何、重新运行 LF 优化。报告中不能把前两类说成本轮重新优化的结果。

如果确实缺少所需几何，只在 lf_data_preparation 中调用原 LF 的已有接口，以明确的算例、参数、种子和运行预算生成。新 LF 优化需在对应阶段计划中说明范围；不自行扩展参数扫描，不改变优化目标，不为获得更好 HF 表现而反复调整 LF。

首个交接演示至少包含一个真实优化得到的反向器和一个真实优化得到的夹持器。手工结构用于单元/桥接验证，但不能冒充 LF 优化候选。

如果上传快照包含 handoff、geometry.npz、outline.json、final_densities.npz 或类似文件，要追踪全部引用。不能仅复制顶层清单而遗漏它在旧目录中引用的文件；也不能把不同版本的数据格式当作已经统一。

保留所有已有候选的来源、状态及已存在资产，不因“未入选本批 HF”而删除。当前交接子集与完整候选档案分别表达；数据去重不应抹掉不同生成记录或生成成本。首轮不要求把全部档案都进行 HF 分析。

## 五、HF 管理的数据契约

先提出最小可用数据规范，用一对真实几何验证，再扩展。优先文件型数据集与索引，例如 JSON 配合 NPZ 或 HDF5；不要先建设服务端数据库、网页管理系统或通用数据平台。

至少分清四类对象：几何资产、生成记录、物理任务、评价记录。相同几何可以有多个来源，也可以在不同任务或不同求解版本下得到多次评价，不能只有一个不断覆盖的“HF 分数”。

### 5.1 几何资产

必须无歧义表达：

- 几何标识、算例类别、格式版本、来源标识。
- 实际进入分析的二值实体分布；约定 0/1 含义。原始连续密度可作为来源数据另存，不能与正式几何混用。
- 数组形状、行列对应物理方向、原点、坐标轴、单元中心/节点语义及物理尺寸。不能只存一张 PNG。
- 长度单位、单元尺寸、面外厚度，以及半模型/全模型和对称面的描述。
- 设计区、被动实体和被动空区；需要用于体积等资格判断的分区信息。
- 支承和输入/输出端口的物理区域描述及方向；端口采用的平均权重规则。旧节点编号只能作辅助，不能成为跨网格唯一接口。
- 从原密度到当前几何的阈值、清理等已有处理及实际结果。若有轮廓，说明闭合、外边界/孔洞、方向和单位规则。
- 完整性标识；几何身份必须考虑实际数组及物理尺度，不能只靠文件名，也不能把不同尺寸的相同像素图当作同一结构。

第一版冻结一种权威几何表示。图像和轮廓若只是派生显示文件，不得反过来无记录地覆盖权威几何。包内引用使用可搬迁的相对路径，来源路径只作记录，不作 HF 运行依赖。

### 5.2 几何资格不等于存档资格

分别表达“文件可读”“几何符合本任务约束”“求解成功”“达到目标功能”。

对机构承担传力的主体检查共享边四邻接、角点连接、端口和支承保持、材料用量及必要的物理尺寸指标。工件与机构本就应有间隙，不能要求整个接触场的所有实体组成单一连通分量。

角点连接、细颈或体积超限的结构可以留在诊断档案中，但不能无标识进入正式合格池。四邻接也不自动保证没有细颈或制造合格。

缺失资格阈值时，输出测量值和 pending 状态，不自称已经满足约束。不要在 HF 内自动补杆、填孔、增厚、平滑或反复二值化以使分析成功。确需几何变换时，作为显式、统一的转换步骤，记录前后差异和新的几何身份。

HF 网格可以细化，但要区分“同一几何上的离散细化”与“几何发生变化”；扩大第三介质域也不能悄悄缩放机构或改变其实际支承。

### 5.3 生成记录与物理任务

生成记录保存原方法、参数、种子、实际几何来源及可获得的 LF 指标；这些不是每个候选自动继承的 HF 工况。

HF 物理任务独立配置材料、本构、二维假设、输入控制及路径、输出负载或工件、支承和对称条件、指标符号及共同资格要求。同一算例内全部候选接受同一个版本的任务；反向器与夹持器分别定义任务，不混合排名。

源 LF 的输入/输出弹簧和力幅值只属于来源记录，不能直接变成候选各自的 HF 负载。材料、行程、输出弹簧、工件尺寸及许可应变等参数，必须标明来自用户决定、原始基准，还是待标定试点。

目前未确定的研究参数不得伪装成已冻结决定。基准复现可以使用论文参数；不能把它们自动用于所有项目结构。未来阶段的问题不应阻断当前单元验证。

## 六、HF 的功能范围与参考实现策略

正式接口的语义应接近：

    result = evaluate(geometry_file, task_config, solver_config)

固定后两者后，对外才能简化成“输入几何，输出响应”。提供独立单结构入口，并在验证后增加小批量入口；不把候选生成、候选选择或几何优化塞进 evaluate。

第一版建议先完成二维、有限变形弹性、无摩擦 TMC 的可信正向分析。优先以实际上传的 2026 年 MATLAB 程序作为对账基础；2025 年论文作为对照和升级参考。不要同时改变语言、本构、积分、单元阶次和正则化。

先建立“论文公式—MATLAB 函数—新实现职责—验证方式”的对应表。注意论文正文、附录与压缩包可能不完全一致：复现某个代码版本时记录其真实行为；疑似错误单独标注并以最小试验判别，不静默拼成一个不存在的版本。

### 6.1 保留与移除的内容

保留材料应力、单元残差、一致切线、稀疏装配、非线性增量求解及后处理。

移除设计更新、MMA/OC、设计伴随、密度优化、优化用过滤投影和延拓。删除结构优化不等于删除 Newton 迭代，也不等于不需要对位移的导数。

第三介质是接触模型的一部分。实体之外需要按任务建立第三介质区域，不能照搬 LF 去空洞重分析而删掉所有空区。

### 6.2 必须从源码逐项核实的数值语义

核查二维假设、三维本构到二维的处理、总拉格朗日运动学、应力/应变与剪切分量约定、节点及自由度顺序、积分点与权重、实体/第三介质缩放、正则化作用范围和特征长度。

特别核对上传初始化代码中的 3×3 Gauss–Lobatto 积分，不能因 LF 曾采用 2×2 Gauss 积分而照搬。面外厚度、总力、总刚度、每单位厚度量以及半/全模型倍数要相互对应。

两篇文献的 Neo-Hookean 表达式、正则化尺度与单元阶次不能仅凭同名就视为一致。对本基线的仿射矩形 Q1 单元，HuHu–LuLu 与 HuHu 的关系须按论文和源码核对，不宣称增加一个 LuLu 开关就获得高阶效果。

基线中随变形缩放的 HuHu 弱式残差一般不来自同一个标量能量势。若采用自动微分，对实际残差求 Jacobian；不要用自行构造的总能量 Hessian 代替，也不要擅自对称化切线。

不得为了方便，把论文 C-shape 的整边固定直接复制为项目机构的支座；背景介质边界也可能传力，必须与真实夹具和对称约束分开定义。

### 6.3 必需而有限的求解保障

每个候选从该任务规定的参考状态开始，按完整加载路径求解。可以复用本候选上一增量的解，不默认复用另一个候选的终态。缓存只能保存明确与候选状态无关、且键完整的对象。

检查 J=det(F) 的有效性；非法试探步通过回退/缩步处理，不能取绝对值或截断 J 来伪造有效变形。记录力平衡、位移约束和实际达到的加载水平，残差归一化不能依赖一个在位移控制下为零的外力。

在实际失败证据支持下加入必要的线搜索、增量细分与回滚；不要第一轮开发通用弧长、全动力学及多种非线性求解框架。

不为某一个候选临时修改第三介质刚度、正则化、材料或目标行程以获得好分数。数值缩步按共同规则进行；物理/模型参数变化生成新的评价版本。

达到同一静力平衡不自动证明路径稳定。求解不收敛也不自动证明结构物理失效；状态与结论要区分。

## 七、两个项目任务及输出

### 7.1 位移反向器

按照任务规定的输入位移路径，评价正确方向的输出端口平均位移、输入反力和输出负载响应。

平均端口的功共轭定义为 f=F b、q=b^T u。采用平均位移控制时，应施加 b_in^T u=d_in 并求其共轭反力；不要未经说明替换成端口所有节点刚性等位移。

若采用广义输出弹簧，K_s=k_out b_out b_out^T；说明方向与权重是否固定在参考构形。它不同于每个节点独立接弹簧。

HF 默认不自动继承 LF 辅助输入弹簧。具体输出负载与行程待任务标定；先跑共同任务下的有限变形弹性分析，保存 q_out(d_in)、R_in(d_in) 和变形序列。

### 7.2 夹持器

先验证无工件的非线性运动，再做简单法向接触，最后接入固定位置和尺寸的圆柱工件。第一版可采用明确约束的刚性工件；其圆心、半径、间隙和输入路径属于固定任务，而不是逐候选调整的参数。

不要把 LF 输出弹簧和圆柱同时作为同一个工件重复加载。接触位置由分析产生，不预先把某个输出节点钉在圆柱上。

至少报告夹爪闭合量、输入反力和分侧工件作用力。完整对称工件的净合力可能为零，不能把净合力直接当成夹持力。明确单爪力、两爪向内力之和、符号及半模型倍率。

TMC 没有现成的显式接触压力乘子。分侧作用力提取应与离散残差/虚功一致并经过验证；不要凭应力云图随意拼接“接触压力”。首版先让合力可信，压力分布恢复可后置。

固定工件压紧不等于自由工件抓取稳定；半模型对称不等于已验证非对称失稳。不要超出本任务声称能力。

### 7.3 通用结果

至少返回：原始物理指标、单位及符号、资格判断、数值状态、实际加载终点、必要的路径数据、失败阶段和原因，以及几何/任务/求解版本。

未到达目标工况不能用最后一个收敛点冒充目标性能；失败不能静默丢弃或写成零反力/零位移。约束缺少判据时用 pending，不自动判可行。

标量评分是上述有效结果的派生输出，不是唯一保存内容。能量量必须正确积分并区分实体、第三介质和数值正则化；对不严格保守的正则化模型，不套用不存在的总能量守恒结论。

## 八、Python、JAX 与性能工程

优先选择能够尽快获得可核验结果的单一 Python 主实现。不要求为了比较技术栈，同时维护两套完整 HF 求解器。

JAX 可以用于单元残差及其位移 Jacobian，CPU 稀疏求解可以作为早期基线。自动微分的作用是减少切线实现负担，不代表本项目要向外提供二值几何梯度。

是否采用 JAX、JIT 或 GPU，用小型对账和端到端计时决定。比较相同精度、容差和加载任务下的完整成本，分别记录编译、单元计算、装配、线性求解、数据传输、迭代和失败重试；不能只展示一个单元核加速比。

需要依赖版本、平台支持或 API 信息时，检查实际环境及官方文档，再记录选择。不要沿用旧 LF 的锁文件，也不要凭记忆声称某个 GPU 稀疏接口支持全部需求。没有 GPU 时继续建立可信 CPU 路径，不把硬件缺失变成物理验证的阻塞。

## 九、验证顺序、可视化与滚动里程碑

请自行规划全局路线图。下面是必须覆盖的依赖关系，不是要求一次写完的刚性开发清单：

HF-0：资料核查、范围澄清、数据边界草案、环境能力与近期计划。
HF-1：真实 LF 几何的自包含导出、通用读取器、断开 LF 验证。
HF-2：单元残差/切线和组装验证、原始 C-shape 正向基准。
HF-3：项目位移控制、同任务线性参照、HF0 小变形桥接、反向器试点。
HF-4：接触基准、圆柱工件与分侧力验证、夹持器试点。
HF-5：小批量独立评价、重复性、误差/参数敏感性与端到端验收。

HF-1 与基于手工基准的 HF-2 可以在不混淆证据的前提下交错推进；不需要先完成全量几何档案才开始单元验证。远期如 Q2、HuHu–LuLu、复杂材料、三维或 GPU，只记录触发条件，不提前展开。

验证至少包含：

- 数据往返后几何、物理面积、方向和端口一致；真实反向器/夹持器及一个能暴露翻转错误的非对称标记样本。
- 单元刚体运动、仿射变形、材料响应、残差—切线方向导数；再做小网格装配与边界验证。
- MATLAB 和 Python 在同一实际基准上的定量对账。没有可运行 MATLAB 或原始数字参考时，说明缺口；可给出可运行的参考导出脚本，不能伪造“与 MATLAB 一致”。
- 同任务小变形桥接分两层：非线性 TMC 趋近其自身初始切线，以及初始切线相对实体线性参照的介质/正则化偏差。加载趋零不自动消除寄生刚度。
- 接触需要独立验证；有初始间隙时的小幅 HF0 不能代替接触验证。
- 在少量代表几何上分别检查网格、第三介质刚度、正则化、加载步长的影响，判断它们是否足以改变关键指标和排序。误差过大时标为尚未验证，不能因程序收敛就称为高保真真值。
- 同一输入重复调用及 A–B–A 顺序测试；断开 LF 后仍可运行；批处理中一个候选失败不抹掉其他结果。

容差必须说明比较量、尺度、参考及允许的离散误差，不给所有测试统一套一个极小数字，不根据已见结果反向放宽验收来凑 PASS。

每个重要阶段提供实际可查看的图：输入与导入几何、支承/端口/介质分区、变形路径、位移—反力曲线、误差或参数变化曲线。图上明确单位、符号和加载水平；保存绘图原始数据。不能只放一张漂亮终态云图。

## 十、推进方式与本轮输出

采用“全局路线图 + 最近一个详细阶段”的滚动方式。不要一次性给出几百项未来任务，也不要只交架构文档而不规划最近可验证的功能。
