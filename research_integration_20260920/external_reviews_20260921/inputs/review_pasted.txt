## 一、先明确：这份代码应按自己的阶段验收

本轮只审查明确上传的 `Compliant-TO-TMC-main.zip`。它使用的是 `hf_eval` 包，有自己的 HF0—HF4 验证记录、实现冻结和准入机制，不能直接继承另一条 `tmcn` 仓库已经完成的 P3/C1 状态。

当前 HF4-C2 的主要任务是一个**矩形实体／背景／障碍的压缩诊断**：实体为 \(2\times1\) mm、初始间隙 0.25 mm、\(E=100\ \mathrm{N/mm^2}\)、厚度 1 mm。这不是前一条研究线中 \(80\times40\) mm 夹持器的固定评价任务。因此，不能拿这里约 71.4 N 的诊断净力与那里的夹持标签直接比较，也不能仅凭这些诊断就宣布可以替换正式 HF 标签器。

这不意味着退回起点。**已关闭的 C0/C1 保持各自原验收范围；本轮只处理 C2 新暴露的问题及依赖。**

**没有执行新的 LF 优化、生产 HF 路径或细网格计算；没有修改上传源码、删除原数据或写入远端仓库。**

## 二、代码审查：一个当前阻断，两项后续前置

### 当前阻断 B1：细网格末态仍未通过，稳定 \(F\) 尚未实现

实际数据如下：

| C2 案例         | 求解器状态   | 独立准入     | 通过状态／总状态 | 检查通过／总数 |
| ------------- | ------- | -------- | -------: | ------: |
| `padding_2p5` | success | pass     |    19／19 | 589／589 |
| `outer_free`  | success | pass     |    19／19 | 570／570 |
| `mesh_h00625` | success | not_pass |    20／21 | 650／651 |

细网格最后一个状态的原定检查为：

$$
\frac{\|f_{\mathrm{prod}}-f_{\mathrm{HP80}}\|_2}{S_F}
=
1.0943792164\times10^{-11}
>
10^{-11}.
$$

我从实际保存的生产力向量和 HP80 参考字符串重新计算，结果一致。该路径的有效前缀停在 **0.4375 mm**，不能因为求解器返回 `success` 就把 0.5 mm 末态列为通过。

需要准确理解这个失败：**它是完整内力向量的求值一致性检查，不是顶面净力相对误差，不是平衡残差，也不是实验物理误差。** 超出原门槛并不证明结构响应发生了宏观错误，但在不改变已定标准的前提下，确实不能关闭 C2。

当前 `hf_repo/src/hf_eval/split_kernel.py:40–61` 仍按以下方式形成变形梯度：

$$
F=(I+\nabla u_{\mathrm{lift}})+\nabla u_{\mathrm{fluctuation}}.
$$

仓库提出的稳定 \(F\) 方案尚未进入当前实现。

**已有诊断支持的方向。** 我重算已保存的不同算术变体向量：保留生产 \(F\)、只把后续计算换为高精度，误差仍约 \(1.0944\times10^{-11}\)；改用正确舍入的精确 split \(F\) 后，误差降至约 \(6.28\times10^{-16}\)。这支持优先修复运动学求值，但只是对**已存诊断向量**的复算，不是已验证的新 JAX 可微内核。

**影响范围：** 阻断 C2 整体准入及依赖它的新阶段；不自动推翻两条通过路径或 C0/C1 原有结论。

**最小处理：** 沿现有 `HF4_C2_KINEMATICS_REPAIR_PLAN.md`，以新实现版本在固定失败态和少量制造场上验证 \(F\)、完整内力及一致切线／Jv；保持原物理参数、尺度和门槛。不通过放宽容差、替换高精度答案或直接重复求解来“补过关”。

### 下一次新路径前置 P1：完整科学协议没有在派发前校验

这是本轮发现并实际构造反例的问题。

`run_contact_c2_isolated.py` 会检查实现哈希、案例、资源和执行顺序；但完整的材料、求解控制、目标等科学配置检查，主要在后续 `audit_contact_c2.py` 中进行。

我只将协议的 `solver.tolerance` 从 **\(10^{-9}\)** 改为 **\(10^{-3}\)**：

* 独立审计的协议校验会拒绝；
* 隔离启动器仍能运行到子进程派发位置；
* 审阅探针在这里截断，没有启动子进程。

**影响范围：** 不是绕过最终准入，也没有证据表明已完成的三条路径用错参数；问题是未来一次协议误改可能**先花掉求解预算，再被审计拒绝**。

**最小处理：** 下一版启动器在派发前复用完整科学配置校验，增加一个“改变 solver 参数不能进入 subprocess”的替身测试。原冻结实现保留；新算术版本明确更新源码身份，不顺带改变任务容差。无需建立新的签署或权限系统。

### 瘦身执行前置 P2：必须保留可还原的来源依赖

当前 C2 复读并不只依赖一份 `fields.npz`。本轮拟外置的文件中，有 **88 个 C1 文件、约 145.16 MB** 同时属于 C2 的来源依赖。只恢复“当前失败态”，而不恢复必要的历史来源，复读会正确地拒绝。

**影响范围：** 直接删除大文件会破坏当前清单校验、历史复读和来源追踪。

**最小处理：** 无损打包原文件、记录原相对路径及哈希；先验证双副本与新目录恢复，再从默认工作树移出。复用仓库已有的 `handoff.py fetch-evidence`，而不是重新开发数据管理平台。

### 非阻断改进与未来研究

当前文档已区分弱式节点反力、材料边牵引和真正的接触压力，这个限定应保留。不要仅凭某个负节点项判定物理接触失效，也不要仅凭合力接近就宣布一般接触正确。

当前发布包仍为 0.5.0、C2 功能在源码树中，README 已说明；这不是本轮必须重发版本的缺陷。一般部分接触／释放、真实机构资格、跨网格精度和最终候选排名，应在后续各自明确任务中验证，**不加入这次算术修复或瘦身的验收范围**。

### 1. 第一轮目标：约 125.56 MB，不追求极限压缩

下面是本轮已经测量、并在独立候选目录中做过局部功能检查的方案：

| ------------------------------------------------ | -------------: |
| C2 的 `experiments/` 原始运行与审计详情                    |      353.95 MB |
| C2 公开复读的 `details/`                              |      248.04 MB |
| C1 的 `A0_*`、`Aalpha_*`、`TMC_*` 运行目录              |      180.16 MB |
| C0 集成结果 `research_integration_20260920/results/` |       71.97 MB |
| 历史 repair 的审计、split preflight 等完整记录              |      225.75 MB |
| 早期 HF4 审计与固定态 probe 记录                           |       35.24 MB |
| **合计外置**                                         | **1115.10 MB** |
| **默认保留**                                         |  **125.56 MB** |

上述数字没有把“重复文件节省”再次相加，避免重复计数。

**全部 `hf_repo/`、全部规范几何数据、协议、来源索引、测试 fixture、阶段摘要及现有图保留。** 第一轮不必再外置几何，也不必追求几十 MB 的极限目标。[逐文件候选与原始哈希](sandbox:/mnt/data/astra_tmc_review/evidence/storage_migration_candidate.json)

### 2. 外置不等于丢弃，也不等于改变科学表示

建议维持三个简单层次：

| 层次           | 放什么                                      | 日常是否随源码携带 |
| ------------ | ---------------------------------------- | --------- |
| **代码与轻量结果**  | 源码、测试、小 fixture、规范几何、协议、摘要、图、资产索引        | 是         |
| **不可变科学证据包** | 完整成功／失败运行、split 双数组、高精度字符串、接受态、控制历史、审计详情 | 否，按需取得    |
| **独立复读目录**   | 按原相对路径恢复的所需证据及匹配源码                       | 仅复读时建立    |

不要降低浮点精度，不要把 HP80/120 字符串截短，不要重新格式化已冻结 JSON 来制造新哈希，也不要以“可以再算出来”为理由丢弃失败记录。

当前复读入口会在运行目录内新建详情，因此应在**独立恢复副本**上执行，而不是向不可变归档原树写结果。

### 3. 功能保留已经有初步证据，但尚未完成生产迁移

本轮候选工作树移出了上述约 1.115 GB 数据后：

* 同一相关测试集合仍为 **142 通过、1 相同原因跳过**；
* 反向器与夹持器两个规范几何均可读取。

这说明日常开发和这些核心路径不需要每次随仓携带全部详细记录。

但还不能把它称为已经交付的瘦身版本：**资产尚未发布、清单尚未分层、全部归档恢复尚未验收。** 当前旧 `verify` 仍要求完整文件集合，这是正确行为，不能为了通过而泛化“缺文件允许跳过”。

最小迁移顺序应为：

**原字节归档 → 双副本校验 → 空目录恢复并核对依赖 → 候选测试／复读 → 更新轻量与完整校验范围 → 最后移出默认工作树。**

### 4. 区分“工作树变小”和“Git 历史变小”

本轮的 **125.56 MB** 是默认工作树／源码快照目标，不是对完整 Git 历史体积的承诺；附件没有 `.git`，无法测量历史对象占用。

仅添加 `.gitignore` 不会让已经跟踪的大文件停止被跟踪，需要在资产安全保存后处理当前索引；`export-ignore` 可用于生成轻量归档，但也是归档导出规则，不是历史清理。([Git][1])

本次方案**不建议重写历史、不强推，也不默认引入 LFS**。优先解决日常工作树、下载快照和交接包的负担；完整历史是否另做迁移，属于单独决定。
