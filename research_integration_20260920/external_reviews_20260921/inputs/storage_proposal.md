# Compliant-TO-TMC 可恢复瘦身方案

这是基于本轮上传ZIP的实测方案，**不是已经完成的仓库迁移**。计量采用十进制MB=1,000,000字节；二进制MiB单独标明。

## 1. 先确定瘦什么

| 部分 | 实测MB | 说明 |
|---|---:|---|
| ZIP附件 | 417.16 | 已压缩的单快照；不含Git对象库 |
| 全工作树普通文件 | 1240.66 | 3426文件，不含虚拟环境和.git |
| hf4_c2_diagnostics | 632.47 | 最大项，含状态审计和复读副本 |
| hf4_repair_results | 238.29 | 历史路径、HP审核、修复中间证据 |
| hf4_c1_results | 189.14 | 选定路径、旧失败前缀和高精度详情 |
| research_integration_20260920 | 74.34 | C0来源集成、路径与审核 |
| hf4_results | 39.53 | 原失败与旧版本证据 |
| geometry_dataset | 25.81 | 规范几何及历史集合；首轮全部保留 |
| hf_repo全部 | 7.06 | 包括源、测试、参考fixture、脚本、配置和旧wheel |
| 其中src | 0.291 | 真正运行内核很小 |
| docs | 0.489 | 删除文档不会解决体积问题 |

按文件类型，普通`.json`为1118.24MB，约占90.13%。`.npz`只有27.86MB。**因此只外置NPZ，或删除几份Markdown，收益很小。** 本仓已经对新控制器使用无损gzip，但逐态HP字符串详情与历史审计仍占主体。

全树精确相同字节的重复组295组，保留每组一份时理论可省276.88MB。最明确的是C2公开复读的40份详情与原审计逐字节相同，重复248.04MB。

这不意味着可以删掉复读的证明/回执，也不意味着可把40次复读记为新增40个物理状态。先分层保存；以后可用“路径→同一字节对象”的映射减少档案重复，但必须能恢复两个原路径。**本方案不要求现在建设内容寻址存储。**

## 2. 推荐结构：代码轻，科学证据完整但按需恢复

```text
Compliant-TO-TMC/
  hf_repo/                    # 所有代码、配置、测试、小型参考
  docs/                       # 目标、版本、当前状态和准确限定
  geometry_dataset/           # 首轮保留全部几何，避免动输入边界
  handoff/                    # 主树清单、资产索引、旧清单身份
  tools/                      # 校验、按需恢复、复制树准备
  hf4_c2_diagnostics/...       # 摘要、图、协议引用、诊断脚本和资产入口
  其他已保留历史摘要/图...

独立档案位置或既有Release：
  c0_runs_v1.zip
  c1_runs_v1.zip
  c2_runs_v1.zip
  c2_readback_details_v1.zip
  hf4_repair_raw_v1.zip
  hf4_original_raw_v1.zip

独立复读工作树（按需建立，不再次纳入Git）：
  replay/<run-id>/
    hf_repo/                  # 对应冻结源码，而不是随意用最新内核
    hf4_c1_results/...         # C2来源依赖需要的C1数据
    hf4_c2_diagnostics/...     # 原相对路径恢复
```

不要求引入LFS、DVC、数据库或对象存储服务；现有`tools/handoff.py fetch-evidence`已具备资产/成员SHA检查和冲突拒绝，优先扩展它。资产存储位置和并发/压缩等级由实施Agent在现有权限与资源内决定；新公开上传仍须遵循现有来源许可边界。

该保守候选保留全部hf_repo、全部geometry_dataset、当前所有文档与外层科学摘要/图，不靠删除功能、单测或几何来减重。其相关测试在隔离目录实际142通过/1项原有私有来源跳过，两个规范几何能读取。

后续若125MB仍偏大，再评估几何历史archive（25.25MB）、重复绘图和过大的可重建展示表；不是首轮必须。禁止以一个统一文件大小阈值自动清理所有JSON。审计详情虽大，恰是本次发现失败与定位原因的证据。

**重复量不要重复记收益：248.04MB复读副本已经包含在1115.10MB外置量中，不能再相加声称多省一次。** 科学总存储量也未必随工作树等比例下降；本轮目标是小源码/交接载荷和可恢复证据，而不是毁掉数据。

## 4. 保证不影响功能的四个条件

### 4.1 原字节保留，而不是“语义近似相同”

每份资产内保留原始相对路径、字节数和SHA256；使用ZIP/tar+gzip等无损封装直接压缩原文件字节。不要解析JSON后改缩进、排序键或缩短HP小数再写回；那会改变冻结哈希。

绝不将`u_lift`与`u_fluctuation`合并成一个显示位移，不将float64变float32，不缩短HP80/120字符串。保留失败态、阶段起点、插入态、完整控制器、每次接受记录、回执、旧失败审计和补充说明。各存盘状态即使物理d相同，也可能有不同的阶段/控制器身份，不能按d去重。

### 4.2 新主树清单与旧科学清单分开

旧 `handoff/repository_manifest.json` 覆盖3425个文件；若直接删除大目录，默认verify会失败。这是正确保护，不应取消校验。

保留旧清单原件及其身份作为完整快照说明；为新的轻量交付生成新主树清单，再由资产索引覆盖外置成员。新版本的 `verify` 检查当前主树；`verify --asset ...`或已有等效模式验证指定恢复资产；`verify --full`只有在全部声明的历史资产均存在并通过时才算完整。

原C2协议、来源清单、结果标签、失败门与原核验输出不为瘦身重签。需改动的是交付层索引和工具，不是科学运行事实。

### 4.3 原相对依赖必须可恢复

C2并非只依赖一份model和最后一个NPZ。当前saved-field admission166项中，164项公开可取；首轮方案外置其中88个C1文件，145.16MB。`audit_contact_c2_readback.load_run`严格核对它们。

因此C2复读资产必须声明需要的C1基线和公开source/admission文件。不能把它们外置后在审核器中增加通用“缺了就跳过”。既有两份未公开MATLAB源码仍沿用**恰好两项**的专用说明，不扩大例外。

冻结审核器限定协议在相同repo树，且会在run下写新详情。复读应将对应冻结源码与全部所需资产恢复至同一**独立树**，不要直接在冷冻原目录执行，更不要从最新版源码目录跨越多个不相关数据根拼接。

### 4.4 两级回归，不用跳过测试制造瘦身成功

**轻量开发级：** 源码导入、两个规范几何读取、当前142项相关测试保持相同结果；只保留原先因私有来源产生的那一项skip。逐步对原有全套测试做依赖核查，常规单测小fixture继续留仓库，不以缺资产批量skip。

**资产恢复级：** 新空目录恢复资产，逐文件字节和SHA匹配；复验公开来源166中的164项；至少覆盖一条通过路径及失败细网格路径的保存数据读取、前缀/力误差复算。应得到同样的两条pass和一条not_pass、细网格前缀0.4375mm与末态1.0943792e-11。

第二级不要求重新求解力学路径；它验证的是存储移动没有改变科学证据。所有恢复失败/路径冲突仍显式报告，不默默覆盖不同文件。

本轮仅完成候选目录的相关测试与几何读取，以及原树存盘数据复算，**没有完成生产资产发布、全量压缩恢复或新主树清单实现**。所以不能直接把隔离候选目录作为“已经完成瘦身的可发布仓库”。

## 5. Git体积与ZIP体积不能混为一谈

本轮没有.git，无法量化历史对象库、pack、clone增量或旧blob存量。125.56MB是候选工作树普通文件量，不是对下一次完整clone下载量的承诺。

- `.gitignore`只影响未跟踪文件，不能让已经跟踪的大文件自动退出Git。迁移验收后需要显式将对应路径从新HEAD移出并添加忽略规则，但旧提交仍保留。
- `git archive`可利用`export-ignore`生成不含指定证据目录的轻量源码交接包；必须随包提供资产索引与恢复说明。它是导出载荷优化，不是历史对象库清理。
- 不默认使用LFS、不重写历史、不强推，与既有政策一致。若用户以后明确要缩小完整Git历史，这是另一个需要授权、备份和协作安排的任务；本阶段不处理。

## 6. 普通工程决策与所有者决策

实施Agent可决定资产的合理分卷、压缩等级、小fixture组织、CLI参数形式和摘要写法；不必逐项向所有者询问。

需要所有者另行明确的是：改变公开/私有发布范围、重写历史/强推、使用新的付费存储、删除唯一原始副本、修改物理/数值门槛、新求解或扩大研究范围。这些都不是本瘦身方案的默认授权。

## 7. 最近唯一实施阶段

**HF4-C2-S0：可恢复外置。** 先有清单与资产，再做双副本/空目录恢复，最后更新当前主树交付与默认忽略。当前HF4-C2仍保持partial，所有失败证据保留；本阶段不改稳定F、不跑新路径。达成两级验证即关闭存储阶段，不为实现通用云存储或完美去重继续拖延。
