# HF-2 修正前求解器独立只读审阅

2026-09-13。本次仅阅读源码、测试和既有证据，未运行数值计算、未修改生产代码或原始资料。审阅范围是 `tmc.py`、`tmc_benchmark.py`、相关测试，并沿调用链核对内核及独立对账程序。以下区分已发现的验收缺口、尚需小试验排除的因素和与当前 C 形无关的通用接口问题。

## 结论与最小修正边界

未发现当前 C 形的 DOF 顺序、COO 行列索引、内外力符号、目标串接或失败状态回滚存在明显实现错误。既有小网格跨语言证据也支持这些部分正确，不能据此声称强压缩态的浮点误差已全面排除。当前确定的缺口是：求解器只用同一个生产残差作内部停止判据，该表达式的误差已足以跨越外部10⁻⁸验收门槛，且没有为表达式误差留出显式裕量。

建议保留通用 `NewtonSettings.tolerance=1e-8` 默认值及显式覆盖能力；在**新的 C 形求解配置**中明确设内部停止值10⁻⁹，保留外部验收10⁻⁸。新配置必须单独标识表达式/求解版本、实际内部容差和原外部判据。不能通过改默认值而隐式改变所有调用，也不能只收紧旧病态表达式就承诺问题解决。稳定残差及其实际 Jacobian、小范围算术预算检查先行。

现有 [三状态精度取证](../hf2_results/residual_sensitivity_001/summary.json)支持逆 C 行列式消去为主要已定位因素；它不是对装配、线性解和所有后端运算的排他性证明。本轮修正应保留下面的有限交叉核查，而不先扩展为通用求解框架。

## 2. 必须正视的验收缺口

### A. 同一生产残差是唯一内部收敛门槛

`tmc.py:254` 只判断 `measured.relative_residual <= settings.tolerance`。这个测量来自刚才的生产 kernel/assembly，没有独立表达式或误差预算参与。既有三个冻结状态已经证明：“生产存档 residual≤10⁻⁸”不足以保证同一数学弱式的较稳定重算≤10⁻⁸。它不是由文字标为success就能解决的状态问题。

有限修正应让生产主残差本身采用经验证的稳定等价形式，并对该实际残差自动微分；再由明确的内部裕量和独立外部重算共同验收。Decimal留在开发取证；不要把它变为通用生产运行依赖。原存档及其失败复核不能被新配置覆盖。

### B. 全局合力与固定值只记录，未进入通用 newton 的成功判断

`metrics` 返回 `global_force_balance` 和 `fixed_displacement_max`，但 `newton` 只判自由残差。固定 DOF 由零初值和只更新free保持，因此当前实现正常调用下不是已观察到的错误。全局合力还检验装配平移不变性，不能由单个节点残差阈值逻辑上替代。

目前阶段对账程序另行执行这两项门槛，整体HF-2没有因生产success而自动PASS，这一分层应保留。若新版基准希望“接受checkpoint”本身包含全部冻结条件，可在基准验收层明确检查固定值、J、合力和独立残差，再更新整体验收状态；不要把针对 C 形的量纲/尺度常数偷偷放进通用 API。

### C. 两条 JIT 执行路径在近阈值状态下尚无专门精度预算

`tmc_kernel.py:166–179` 分别编译带Jacobian和不带Jacobian的函数。Newton基点和最终收敛检验使用前者，Armijo试探使用后者。二者调用同一数学 `_residual_with_aux`，但编译优化/运算重排可导致双精度细差。

已有 `test_batch_singleton_mixed_material_and_no_tangent_consistency` 检验温和状态的一致性，并有差分测试；不能自动覆盖 min J≈10⁻⁴至10⁻⁵ 的存档状态。这里可能造成边界附近回溯/迭代次数差异，或较严格内部容差下的噪声平台。最终带切线基点会重新检查，因此这种差异本身不是已发现的“试探直接假收敛”漏洞。只需对三个冻结状态比较新实现两模式的全局自由力，按绝对力误差预算报告；不要求逐位相同。

## 3. 其他原因的限定排查，避免过早归因

1. **局部积分与全局累加。** 保持同一份局部单元力，分别用当前bincount、独立scatter和逐DOF高精度/补偿求和作一次小诊断，可隔离全局累加误差；不要同时更换本构表达式和装配方法后将改善全部归因于其中之一。Q1节点的贡献数有限，既有小网格数值一致且索引正确，目前没有证据支持生产装配器重写。
2. **线性求解精度。** 当前只检查LU是否抛RuntimeError及δu是否有限，没有记录线性方程的后向误差。对修正试验中的代表Newton步记录 `‖K_ff δu+r_free‖/(‖K_ff‖‖δu‖+‖r_free‖)`（各范数种类固定）。非线性重新评估可防止差的线性解直接成为成功，但LU误差仍可能妨碍达到内部裕量或改变回溯。先记录，不预先引入迭代改进、正则对角或替代稀疏后端。
3. **外载尺度。** 当前分母是完整 `‖λF0‖`，与原基准一致，非自由部分没有剔除。C形全部外载都在free DOF，因此这不是本例超限原因。一般API若给固定DOF施加很大外载，分母可能掩盖自由系统误差；应在未来任务定义中选择或限制该语义，不能本轮改成另一尺度并据此重新宣称原C形通过。
4. **原目标值与中点。** 参考入口容许源/NumPy linspace 的微小舍入差，并随后复制实际源targets；compare程序按精确源目标匹配。这一设计正确。修正路径继续使用原100个源值，不另生目标序列、不将二分目标混为原目标。
5. **刚体模式与奇异性。** `_check_support`只检查全局三个刚体模式被约束，不证明每个不连通子域都受约束，也不证明平衡解唯一。当前C形网格全域连通且所有介质倍率为正；不是已观察到的当前根因。零载荷下奇异模型仍可能有零残差平衡，应将唯一性/几何资格与数值平衡分开，留待对应接口扩展，不扩大本轮范围。
6. **停止与运行时间。** 内部在核调用前后、回调后查时间，不会中断正在执行的单次LU/JIT；外层已有进程时间/RSS监控提供硬停止证据。时间记录本身不解决残差精度。无需为本轮重建调度器。

## 4. 内部10⁻⁹应该放在哪里

建议在新的benchmark执行配置中显式构造 `NewtonSettings(tolerance=1e-9, ...)`；保留通用默认10⁻⁸。物理基准仍绑定同一个上传ZIP、网格、材料、载荷和原100目标；求解配置和残差实现使用新版本/哈希，明确记录 `internal_newton_tolerance=1e-9` 与 `external_free_residual_tolerance=1e-8`。

`run_cshape` 目前在 `tmc_benchmark.py:99` 只覆盖 time_limit，依赖其他默认参数。这里必须显式选择新profile，或接受经验证的配置对象；旧v1信息保留。不要改通用默认后继续用同一基准标签来表示两套求解策略。`config['solver']=asdict(settings)`已有完整落盘机制，可保留并补充新profile身份和外部验收定义。

图中10⁻⁸水平线当前表示冻结外部标准。新版应标明该含义，并可增加10⁻⁹内部线；不能因为内部值改变便把图上外部判据一起替换。通用 `solve_path` 的success应继续准确表述为它所用数值判据通过；基准整体的独立验证状态另列，不能由success自动升级。

10⁻⁹是本次拟议的安全裕量，不是所有几何/任务适用的精度常数，也不是稳定性证明。应先用已冻结强压缩状态及有限修正步检验能否满足算术误差预算；若观察到收敛平台，报告真实余量与原因，不提高外部10⁻⁸门槛，也不靠多个完整路径重试选最好结果。

## 5. 进入完整修正路径前的有限测试建议

不增加全套泛化测试。与本轮修正直接相关的最小集合是：

- 复用原刚体/仿射/厚度、材料与正则化分项、实际残差方向导数、小网格三方装配及16个普通数值参考；确认稳定表达式改写保持同一数学模型和全部HuHu导数。
- 三个冻结强压缩状态上比较新kernel的带/不带切线残差、独立直接Piola及已有50位基准；分开记录局部力、全局自由力、归一化尺度，避免把两个残差范数之差当作力向量误差。
- 明确测试通用默认仍为10⁻⁸、新benchmark profile显式10⁻⁹、config中实际值可追溯、外部标准仍10⁻⁸。可以mock求解器检查配置传递，不为此运行完整C形。
- 用受控小状态测试“原目标失败→中点接受→最终目标失败”的递归回滚，确认 reached_lambda、original_target标记及null目标指标；补一个时间/持久化失败的状态测试即可。现有关闭二分的失败测试不足以覆盖该路径。
- 保留既有精确source target校验；最终对完整修正路径逐原目标检查全部原指标和稳定自由残差，不能只检查终点或原三个问题点。

以上建议由根任务纳入本轮冻结修正计划；本次只读子任务没有执行这些测试，也没有宣布修正已经成功。HF-3仍须等待HF-2精度问题闭合。
