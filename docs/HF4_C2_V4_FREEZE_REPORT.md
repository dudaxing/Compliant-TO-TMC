## 3. 预算与停止口径（数值与 v3 相同，只写清楚）

| 层次 | 上限 | 说明 |
| --- | ---: | --- |
| 求解器内部墙钟 | 300 s | 即 `solver.time_limit_seconds`，含内核调用、线性求解与接受态回调；协议 `budget` 中重述，并由校验要求两处相等 |
| 求解子进程外部墙钟 | 700 s | 守卫强制，不覆盖内部 300 s |
| 独立审计子进程 | 1200 s | 与求解分开计 |

- **不自动重试**：指不另开一条路径、不改参数或门槛、不提高资源、不重跑审计。控制器已声明的 Armijo 回溯与至多 8 层二分照常在同一条路径内进行。
- **独立审计**：在求解之后进行，不在 Newton 过程中实时拦截。
- **求解失败**（非零退出）**时**：守卫不派发审计。已落盘的接受态与日志保留；未审计的部分不称为已验证前缀；是否另行审计由所有者决定。
- **超时时**：保留全部已落盘的接受态。只有通过独立审计的连续部分才称为"已验证可比较前缀"。冻结审计要求完整的 controller／completion 清单，因此硬超时只留下逐态文件时不予认证；不增加续算、抢救求解或不完整目录审计功能。
- **验收**：七个原目标与控制规则必须满足。v3 的 21 个接受态只是历史观察，不要求 v4 重复同样的数量。
