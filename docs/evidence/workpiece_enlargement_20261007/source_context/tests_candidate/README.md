# 平均输入端口初猜的隔离功能测试

作者候选，仅静态写入与AST/compile审查；未导入测试模块，未构造模型、运行FE、pytest或渲染。root复制审阅后的测试到正式tests，再按新卡执行。

前三项测试使用原 `test_split_displacement.py` 的一单元与注入残差fixture，第四项使用原真实16单元native fixture；它们验证控制器与API转发功能，不作为 TMC 接触或工件物理资格。

- 非线性 cubic1000、`invalid_above=.15`、不二分、0→.1：原切线初猜给两输入节点`.16/.04`，违反原J门并回滚；新端口分布从`.1/.1`开始，保留原真实KKT LU与`dR`。最终用独立 `brentq` 求解两自由端口的不同位移和反力，核对均值、固定节点、残差与真实LU标志，证明它只是初猜而非刚性绑节点。
- 非零lift形状、非对称矩阵、秩一输出弹簧与有序加载—卸载：逐目标比较独立密集KKT平衡，核对lift、固定、反力、原顺序与预测器应用标志。
- 默认调用与显式`tangent`的数组位、轨迹及LU诊断完全一致；额外注入真正非正J字段，确保`port_projection`仍按原J门失败并保留最后接受态。
- 原16单元native NumPy入口：0→.001 mm，默认与新模式最终位移和反力在原tolerance内一致；验证path与metadata的模式转发、真实预测LU标志、固定、约束、正J及0HP/JIT。沿用原8秒API设置和禁止旧力/JIT的fixture，不扩大测试模型。

测试spy调用真实 `_linear_solve`，没有伪造线性答案。前三项独立参考在隔离代数层；第四项覆盖真实native API参数转发与原NumPy入口。工件接触资格仍须后续实际任务验证。这不是导数修复、J容差放宽或控制器门限变化。
