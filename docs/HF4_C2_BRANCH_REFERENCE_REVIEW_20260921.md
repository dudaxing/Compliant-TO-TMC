## 1. 整体目标与当前状态

整体目标仍是建立独立、可搬迁、任务范围明确的 HF 力学评价后端：仅消费普通几何文件和版本化物理任务，输出带单位、有效性、误差与来源证据的响应。评价可靠后，才研究固定预算下 LF 质量、多样性及任务匹配排序的发现收益。

当前已完成 HF4-C2 三条有界诊断路径及其失败定位、公开数值复读与交接。按既有记录，59 个状态中 58 个通过，1810 个精度门中 1809 个通过；细网格末态完整内力相对误差 `1.094379216402844e-11` 超过原 `1e-11` 门槛。固定场反事实证据把主要误差定位到强压缩下 F 的形成运算，但生产稳定 F 和一致切线尚未实现、验收。C2 未全部关闭，HF5 尚未开始。

上述数字来自已归档证据，本轮未重跑。详情见 [C2 最终报告](HF4_C2_FINAL_REPORT.md)、[尚未执行的运动学修复计划](HF4_C2_KINEMATICS_REPAIR_PLAN.md) 和 [公开复读边界](HF4_C2_PORTABILITY_ADDENDUM.md)。

## 3. 本地核查一：启动前协议校验缺口

外部指出的缺口已由本地三组全拦截探针确认。原 wrapper 检查实现哈希、案例顺序及资源边界，但派发前未调用完整物理/求解合同校验。直接 runner 根据协议构造求解设置，因此未来修复也需覆盖直接入口。

| 探针 | 完整 `validate_protocol` | 原 wrapper 的实际行为 |
|---|---|---|
| 原协议，solver tolerance=`1e-9` | 接受 | 到达被 mock 拦截的派发边界 |
| 仅将 tolerance 改为 `1e-3` | 拒绝：`solver acceptance or control contract changed` | 仍到达同一拦截边界 |
| 错误 implementation SHA | 语义校验本身不负责该哈希门 | wrapper 在派发前 exit 2 |

`subprocess.run` 由抛出专用异常的 mock 替代；其余子进程接口全部禁止且调用为零。真实子进程启动数为 **0**。探针只产生独立协议/准入文件副本、空日志占位及 JSON 记录，没有求解目录、状态 NPZ 或生产 receipt。到达边界不等于下游所有检查会接受，更不等于数值计算成功。

**影响范围：下一次数值执行前置问题。** 三条历史路径的 metadata、completion 及 solve/audit receipt 仍绑定原 v3 协议和 `1e-9` 容差；保存状态仍为两条 pass、一条 not_pass。没有证据表明这些历史结果使用了被放宽的协议。

**最小后续处理：** 在新版本 wrapper 的输出创建与派发之前验证完整合同及获准协议身份，保留原实现/顺序/资源门；直接 runner 入口也进行同门校验。以原协议正对照、单字段篡改及错误实现身份反对照验证。保留冻结 v3 原字节，不能就地修订后仍沿用旧版本身份。这项修复与既有 receipt 顺序门修复不同，也不能由公开 numerical readback 代替执行准入。

证据：[探针结果](../.github_handoff/branch_reference_review_20260921/protocol_dispatch_probe.json)、[探针源码](../.github_handoff/branch_reference_review_20260921/probe_protocol_dispatch.py)。结果 SHA-256：`44590f159c9d287bd908e97df604e5dbd53a3d311fc7a6d95155e3d259d9ad44`；源码 SHA-256：`872f503676543e5bb26b889930f3023b5843bdeb16f0e13f3cd1bc5acfcf0bb3`。
